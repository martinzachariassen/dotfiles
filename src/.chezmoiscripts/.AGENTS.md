# `.chezmoiscripts/` — chezmoi hooks

Scripts here are the only chezmoi-managed code that **executes** during
`chezmoi apply` — templated *commands*, not files. The naming, the guard, and
the lifecycle bucket all matter: get one wrong and a fresh-Mac install skips a
step or fires it at the wrong moment.

## Naming — chezmoi reads the prefix

```
run_<when>_<NN>-<short-name>.sh.tmpl
```

| Prefix | When chezmoi runs it |
|---|---|
| `run_before_NN-…` | Every apply, **before** any file action. |
| `run_after_NN-…` | Every apply, **after** all file actions. |
| `run_once_before_NN-…` | First apply only (chezmoi records success). |
| `run_onchange_after_NN-…` | When the script's **rendered body** changes. |

chezmoi sorts scripts alphabetically by their **full filename** within each
`when` bucket — so the bucket prefix (`run_after_` vs. `run_onchange_after_`,
etc.) always determines order before the two-digit `NN` is even compared. `NN`
only controls order *within* a single bucket (`02` → `02b` → `02e`); it does
**not** order a `run_after_10-…` relative to a `run_onchange_after_05-…` — the
`after` bucket always runs first regardless of NN. Keep numbers sorted within
a bucket; insert `02a`/`02b` rather than renumbering the whole sequence.

**`after` vs `onchange_after`:** anything that **converges installed state**
(brew, mise, plugins) is `run_after_*` — see `docs/lifecycle.md` § "Apply always
converges real state." Anything driven from a declared manifest where re-running
on unchanged input is just noise (vscode extensions, macOS defaults, the closing
summary) is `run_onchange_after_*`.

## Required shape

Every `.sh.tmpl` here must:

1. **Bash shebang.** `#!/usr/bin/env bash`.
2. **Strict mode.** `set -euo pipefail`, or `set -uo pipefail` when the
   script wants to continue past failing items (see
   `02-brew-bundle.sh.tmpl`'s continue-on-error contract).
3. **Darwin guard, near the top, unless OS-agnostic:**
   ```
   {{ if ne .chezmoi.os "darwin" -}}
   echo "→ <step>: not on macOS, skipping"
   exit 0
   {{ end -}}
   ```
   chezmoi runs every script on every platform; without the guard, the body
   fires on Linux too. Only `99-completion` is exempt (pure output, no state).

4. **Stdin reattach when prompting.** chezmoi runs scripts with stdin closed.
   For sudo or `read`, do `exec </dev/tty` and degrade gracefully when no TTY
   exists (CI, launchd). Pattern in `00-sudo-cache` and `04-macos-defaults`.

The bats suite in `tests/chezmoi-scripts.bats` enforces 1–3 statically and
runs every rendered body on Linux to confirm the guard fires before any
macOS-only command.

## Don't reach for chezmoi data inline

Interleaved bash and Go-template directives get unreadable. Pull what you need
into bash vars at the top:

```bash
PROFILE="{{ .profile }}"
ROOT="{{ .chezmoi.workingTree }}"   # repo root — where scripts/, packages/ live
USE_OP="{{ dig "useOnePassword" true . }}"
```

Use `dig "key" default .` for anything that might be absent from older
machines' chezmoi data — `dig "modules" (list) .` on a Mac that hasn't
re-run `chezmoi init` since a module was added would be `<no value>`
otherwise. Module membership itself is a flat list, checked with
`has "macApps" .modules`, not a per-module `.features.*` namespace.

## `sourceDir` vs `workingTree` — the split matters here

`.chezmoiroot` makes `src/` the source dir, so `{{ .chezmoi.sourceDir }}` is
`…/dotfiles/src`. The repo tooling a hook needs (`scripts/lib/*` engines,
`packages/Brewfile*`) lives at the **repo root**, one level up and outside the
source tree. Reach it with **`{{ .chezmoi.workingTree }}`** (the git working
tree = repo root), never `sourceDir`. Same rule for the `{{ include "…" }}`
hash-gate: paths are source-relative, so a root file is `include "../<file>"`.

## Engine code goes in `scripts/lib/`

These hooks are thin drivers. The real work lives under `scripts/lib/` (repo
root) as plain bash — shellcheckable, unit-testable, reusable. Source it via
`{{ .chezmoi.workingTree }}/scripts/lib/<name>.sh`.
`run_once_before_01-install-homebrew.sh.tmpl` is the reference shape:
render-time guard, source `scripts/lib/homebrew.sh`, call its entry point
(`homebrew_install`). `02-brew-bundle.sh.tmpl` and
`run_onchange_after_03-vscode.sh.tmpl` don't fit this shape yet — most of
their install/tap/prune logic is still inline in the hook rather than in a
lib — so don't copy either as the thin-hook example.

## When you add a new script

- Pick the bucket and number; check it sorts where you expect.
- Add the darwin guard (or list it in `tests/chezmoi-scripts.bats`'s exempt
  set if it's truly OS-agnostic).
- Re-run `bats tests/chezmoi-scripts.bats` locally.
- If it has any new pure helper logic, add a `tests/<name>.bats` next to the
  existing suites.
- Update `docs/lifecycle.md`'s "Where each piece lives" table if it changes
  the user-visible flow.

---

This file is named `.AGENTS.md` (dot-prefixed) on purpose: chezmoi treats
**every** non-hidden entry in `.chezmoiscripts/` as a script and rejects
anything that isn't, including `.md` files. The leading dot makes chezmoi
skip it without needing a `.chezmoiignore` entry.
